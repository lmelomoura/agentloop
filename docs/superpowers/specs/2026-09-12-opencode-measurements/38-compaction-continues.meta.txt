So `step_finish.reason: stop` is NOT always the end of the run (README, "um
turno tem um passo por chamada ao modelo... `stop` no último"): the
compaction step ends on one and the session goes on. The normalizer used to
emit the run's result at the first `stop` and ignore everything after it:
this run was filed with the compaction's summary as its final text (no
`RUN COMPLETE`, so UNDECLARED ENDING), 129 turns, and the cost and tokens
up to the compaction (0.1212 of the 0.1466 USD the steps reported).

The CLI retried both times and the run went on to `RUN COMPLETE`; nothing in
the JSON stream marks them. The classifier counted the stderr bytes and filed
the finished run as `warning` ("STDERR: the CLI wrote 2 line(s)...").
